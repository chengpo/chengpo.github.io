In the past few days, I refactored the backend code of this website. I prefer self explanatory code without "boilerplate".
\nI also want the website can be directly runs outside of IDE which enable me to write and preview post from my Linux netbook more comfortable.

\n

Here are the lessons I learned from this code refactoring:

\n

Prefer optional over checking null pointer

\n

"Optional" is one of my favorite Java8 feature.
\n"Optional" postpones null pointer checking to the very end of the data processing flow. The code has no more worry to null pointer exception while processing data.\nI fell like all null pointer checking should be replaced by optional.

\n

A simplified processing flow of loading post is as:

\n
Optional.ofNullable(readTextFile(path))\n        .map(content -> parseMarkdown(content))\n        .map(Optional::get)\n        .orElseThrow(() -> new WebApplicationException(404));\n
\n

The readTextFile() may return NULL in case of failed to open the needed file.\nHowever, code has no worry to null pointer in the middle of the data processing.\nNull pointer is handled at the very end of the pipeline.

\n

Prefer injecting dependency over hard code dependency

\n

I use Jersey framework's build-in dependency injection lib (HK2) to inject dependency of controllers.\nThe 'real' dependency implementation is decoupled from where it is be used.

\n
public class PostsController {\n    @Inject\n    PostRepository postRepository;\n\n    @Inject\n    PaperAdapter paperAdapter;\n    \n    public void getPost() {\n        // ...\n    }\n}\n
\n

The PostController has no idea to the 'real' implementation of the PostRepository and PaperAdapter.\nThose 2 implementations could be easily replaced for testing purpose.

\n

Prefer concise code over verbosity code

\n

Programs must be written for people to read. I believe concise API is also readable and self-explanatory code.

\n
 @Override\n    public Optional<Paper> toCompletePage(Paper.Id id) {\n        return from(id)\n                .with(AppContext::realPagePath)\n                .by(TextReader::completeRead);\n    }\n
\n

The code can be translated to plain English as "Convert to page content from paper id with page path by completed text reader".\nI feel this is most concise code I could have for now. I cannot delete more word from them.

\n

Does it sound good? Please leave comments on issues page .
