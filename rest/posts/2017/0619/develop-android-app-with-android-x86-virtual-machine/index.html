Google suggests using x86 Android emulator to get the best developing user experience.

\n

However, if you like me only have a desktop running Windows and unfortunately with AMD CPU.\nAnd for some reason has trouble with the Genymotion.\nThen the combination of VirtualBox + Android-x86 could be a good option to get rid of the painful ARM emulator.

\n

I believe it won't be a trouble for everyone to download the latest Android-x86 livecd iso and VirtualBox installation file.\nSo, I only list the steps I took to make a comfortable developing environment for myself.

\n

- Create separate partition for GRUB and root file system

\n

Firstly, the Android-x86 installation stuck at the step of GRUB installation.\nI managed to work around this problem by creating 2 partitions.\nThe first partition is for GRUB installation. 100MB is good enough for GRUB.\nThe second partition is for hosting Android-x86 system. I make it as large as 2GB.\nAfter the installation is done, I got around 850MB left.

\n

- Add customized video mode to get a 'portrait' display

\n

By default, Android-x86 runs in landscape mode. Unlike the regular emulator comes with Android SDK.\nVirtualBox does not support screen rotation. So, it won't be feasible to change display 'portrait / landscape' mode\non the fly.\nHowever, we may create new GRUB menu item for a 'portrait' display.

\n
    \n
  • Run command to add custom video mode to the virtual machine which named as "Android"
    • \n
\n
VBoxManage setextradata "Android" "CustomVideoMode1" "480x800x16"\n
\n
    \n
  • Boot Android-x86 into Debug mode and edit the /mnt/grub/menu.lst.\nCopy and paste the first menu item (including the title, kernel and initrd lines).\nOn the 'title' line, append '480x800'. On the 'kernel' line, append 'UVESA_MODE=480x800 DPI=240'
    • \n
\n

- Disable virtual network adapter to skip device configuration

\n

After the first reboot completed, Android OS would request Google Account login to complete the initial device configuration.\nAs an testing emulator, logon Google Account is unnecessary. To avoid it attempting to connect Google service,\nI simply disconnect the virtual network adapter.

\n

- Connect adb to Android-x86 virtual machine via network

\n

Well, the last step is establishing adb connection to the running Android-x86 virtual machine.\nSo, I could install / debug my Android App.

\n
    \n
  • Firstly, press ALT-F1 to enter console after the Android home screen be shown.
    • \n
  • Secondly, run command netcfg to get current IP address. For instance, in my case, the IP address is 192.168.56.101.
    • \n
  • Thirdly, press ALT-F7 to return to the Android home screen.
    • \n
  • At last, run below command in Window Command Prompt window for creating adb connection via network.
    • \n
\n
C:\\> adb connect 192.168.56.101\n
\n
    \n
  • After all of the above steps, we may find the Android-x86 virtual machine in device list of "adb devices" command
    • \n
\n

All right, that's it. Hope it works for you too.

\n\n"}
